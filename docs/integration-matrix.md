# Integration Matrix — AgricPlatform

All external systems are integrated as **provider adapters behind interfaces** (SPEC contract 4): a local stub keeps CI deterministic and the repository buildable without secrets; a production driver is selected via environment flags. The current reference implementation centralises provider stubs and status reporting in `apps/api/src/modules/integrations/` (notably `adapters.ts`, `integrations.service.ts`, and `integrations.controller.ts`); infrastructure-level components live under `infra/`. Provider-specific production adapters may later be split into `apps/api/src/integrations/<provider>/` without changing the contract. This matrix is the single reference for what each integration does, how it behaves locally, what credentials production needs, and how it is verified.

**Verification classes** (from `docs/requirements-traceability.md` §6):
- **Code** — verifiable in CI with stubs, no credentials.
- **Sandbox** — verifiable with test credentials / self-hosted instance; proves the adapter contract only.
- **Live** — requires production credentials and/or a signed agreement; **cannot be live-verified without them**. These remain External dependency items on the launch-blocker list.

Driver flags defined at baseline in `.env.example`: `SMS_DRIVER`, `WHATSAPP_DRIVER`, `EMAIL_DRIVER`, `PUSH_DRIVER`, `PAYMENT_DRIVER`, `SEARCH_DRIVER`, `WEATHER_DRIVER`, `LMS_DRIVER`, `COMMUNITY_DRIVER` (each `stub | sandbox | production`). Integrations without a driver flag yet are noted as **flag TBD** and default to stub/no-op.

## Wave P1 live driver implementations

Real HTTP drivers now sit behind the adapter port in `apps/api/src/modules/integrations/drivers/`. Every call uses the global fetch with a 5-second `AbortController` timeout and no in-adapter retries (callers own retry policy); errors map to `ProviderConfigError` (fail closed), `ProviderHttpError` (4xx/5xx) or `ProviderRequestError` (timeout/network). The stub stays the default driver everywhere; in production the API refuses to boot when a non-stub driver lacks its credentials (`assertProductionDriverConfig` plus eager driver construction in `IntegrationsService`).

## Phase 3 integrations

Wave P5a implements the federated model for these systems: identity resolution via phone/NIN with consent, inbound data tagged with source + consent timestamp, and fail-closed stubs by default. Code lives in `apps/api/src/modules/integrations/` — clients under `drivers/`, services + the `/integrations/federation` controller under `phase3/`, storage in `infra/postgres/007_phase3_integrations.sql`. Driver flags: `FARM_RECORDS_DRIVER`, `OFN_DRIVER`, `EXCHANGE_FEEDS_DRIVER`, `FIELD_DATA_DRIVER`, `LENDER_DRIVER`, `EXTENSION_FEED_DRIVER` (each `stub | sandbox | production | live`; a non-stub flag without the full credential set fails closed at boot). Webhook receivers (`/integrations/federation/webhooks/{farmos,litefarm,ofn,lender}`) use a shared-secret `x-integration-token` (`<SYSTEM>_WEBHOOK_TOKEN`); production traffic without a configured token is refused.

## Notes on live-verification limits

1. **Never live-verifiable from this repository alone:** Termii SMS delivery, WhatsApp template delivery, Paystack/Flutterwave live escrow and settlement, BVN/NIN checks (NIBSS/NIMC), NiMet feed, FMARD benchmarks, AFEX/NCX trading, Mojaloop switching, donor MIS imports. Each requires credentials, signed agreements, or regulatory review (⚖ items in `docs/security-compliance.md` §11).
2. **Fully verifiable without third-party credentials:** Meilisearch search slice, OpenMeteo weather path, FEWS NET public-data ingestion, Postgres double-entry ledger, event/outbox contracts, all stub-driver behaviour.
3. **Sandbox-verifiable now, live later:** Keycloak (self-host), Moodle, Discourse, Directus, Paystack test keys, OneSignal free tier, Mailgun/SendGrid sandbox domains, 360dialog sandbox. Sandbox evidence must be labelled `sandbox` and does not close launch blockers.
4. Every adapter must fail closed: unknown/missing credentials fall back to stub behaviour in non-production and to a loud, monitored configuration error in production — never a silent live call with placeholder keys.
